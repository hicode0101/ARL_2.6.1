# ARL 程序部署文档

| 项目 | 内容 |
|---|---|
| 对应版本 | v2.6.1 |
| 支持平台 | Linux only（不支持 Windows）；官方一键脚本仅适配 CentOS 7；Ubuntu 20.04 源码部署见第 2.2 节（蓝本为官方 arm64 镜像 `docker/ARMWorker/Dockerfile`） |
| 部署方式 | ① Docker / docker-compose（推荐）② 源码安装：CentOS 7 一键脚本 / Ubuntu 20.04 手工部署（systemd 服务） |
| 硬件建议 | CPU 4 线程 / 内存 8G / 带宽 10M；资产侦察发包量大，建议云服务器 |
| 对外端口 | **5003（HTTPS）**，默认账号 **admin / arlpass** |

## 1. 方式一：Docker 部署（推荐）

### 1.1 前置条件

- 已安装 `docker` 与 `docker-compose`（Ubuntu：`apt-get install docker.io docker-compose -y`；CentOS 可用官方一键脚本，见 1.5）；
- 能访问 Docker Hub（或已配置镜像加速）。

### 1.2 标准部署步骤（官方 Release 包）

```bash
# 1) 准备目录，下载发行包（内含 docker-compose.yml、config-docker.yaml、mongo-init.js、.env、日志占位文件）
cd /opt/
mkdir docker_arl
wget -O docker_arl/docker.zip https://github.com/TophantTechnology/ARL/releases/download/v2.6.1/docker.zip
cd docker_arl
unzip -o docker.zip

# 2) 创建数据卷（MongoDB 持久化，compose 中声明为 external 卷）
docker volume create arl_db

# 3) 拉取镜像并启动
docker-compose pull
docker-compose up -d
```

启动的容器（`docker ps`）：

| 容器名 | 镜像 | 说明 |
|---|---|---|
| arl_web | tophant/arl | Nginx(80/443) + gunicorn(5003, 3 进程) |
| arl_worker | tophant/arl | 两个 Celery worker：`arltask` 队列（c=2）+ `arlgithub` 队列（c=2） |
| arl_scheduler | tophant/arl | `python3.6 -m app.scheduler` 调度进程 |
| arl_mongodb | mongo:4.0.27 | root=admin/admin，数据卷 arl_db |
| arl_rabbitmq | rabbitmq:3.8.19-management-alpine | user=arl/arlpassword，vhost=arlv2host（端口不对外暴露） |

### 1.3 验证

1. 浏览器访问 `https://<服务器IP>:5003`（自签名证书，需信任）；
2. 使用 `admin / arlpass` 登录；
3. `docker-compose ps` 六个容器（web / worker / scheduler / mongodb / rabbitmq）均为 Up；
4. 首个测试任务：目标填 `example.com`，勾选「域名爆破-测试 + 端口扫描-测试」，执行后任务状态应为 done。

### 1.4 docker-compose 关键配置解读（docker/docker-compose.yml）

| 项 | 值 / 说明 |
|---|---|
| 端口映射 | `"5003:443"`（HTTPS）；HTTP 80 默认注释未映射 |
| web 挂载 | `./arl_web.log:/code/arl_web.log`（访问日志）；`./config-docker.yaml:/code/app/config.yaml`（配置注入）；`./image:/code/app/tmp_screenshot`（截图持久化）；`./poc:/opt/ARL-NPoC/xing/plugins/upload_poc`（自定义 PoC 上传目录） |
| web 启动序列 | `gen_crt.sh`（生成自签证书）→ `nginx` → `wait-for-it mongodb:27017` → `wait-for-it rabbitmq:5672` → gunicorn |
| worker / scheduler | 同样挂载配置；worker 日志 `./arl_worker.log`；scheduler 仅挂配置 |
| mongodb | `arl_db:/data/db` 持久化；`./mongo-init.js` 只读挂载到 `/docker-entrypoint-initdb.d/`（**仅卷首次初始化时执行**，创建 admin/arlpass 账号） |
| rabbitmq | 日志限制 json-file 1M×10 |
| 版本选择 | `.env` 中 `ARL_VERSION`（发行包默认 latest） |

> 注意：compose **未配置 healthcheck**，依赖 wait-for-it.sh 等待依赖就绪。

### 1.5 CentOS 7 一键安装 Docker 环境（misc/setup-docker-arl.sh）

脚本流程：安装 `python36 git htop vim` → pip 安装 `docker-compose` → 安装 Docker CE（官方 yum 源）→ 启动 docker → clone ARL 到 `/opt/ARL` → `cd /opt/ARL/docker && docker-compose pull` → `docker volume create arl_db` → `docker-compose up -d`。

```bash
wget https://raw.githubusercontent.com/TophantTechnology/ARL/master/misc/setup-docker-arl.sh
chmod +x setup-docker-arl.sh
./setup-docker-arl.sh
```

## 2. 方式二：源码部署（CentOS 7 / Ubuntu，安装目录 /opt/ARL）

### 2.1 CentOS 7 一键安装（misc/setup-arl.sh）

```bash
wget https://raw.githubusercontent.com/TophantTechnology/ARL/master/misc/setup-arl.sh
chmod +x setup-arl.sh
./setup-arl.sh
```

脚本执行内容（顺序）：

1. 写入 MongoDB 4.0 官方 yum 源；
2. 安装系统包：`epel-release python36 mongodb-org-server mongodb-org-shell rabbitmq-server python36-devel gcc-c++ git nginx fontconfig wqy-microhei-fonts unzip wget`（中文字体用于截图渲染）；
3. 建立 `python3.6` 软链，ensurepip 并升级 pip；
4. 安装工具链：nmap 7.91（rpm）、nuclei 2.9.15（GitHub release，随后 `nuclei -ut` 更新模板）、wih（`wih_linux_amd64` → `/usr/bin/wih`）；
5. 启动并自启 `mongod`、`rabbitmq-server`；
6. clone 源码到 `/opt/ARL` 与 `/opt/ARL-NPoC`（NPoC 执行 `pip3.6 install -r requirements.txt && pip3.6 install -e .`）；
7. 下载 ncrack 与 ncrack-services（`/usr/local/bin/ncrack`、`/usr/local/share/ncrack/ncrack-services`）；
8. 下载 GeoLite2 ASN/City 数据库到 `/data/GeoLite2/`；
9. 初始化 RabbitMQ：创建用户 `arl/arlpassword`、vhost `arlv2host` 并授权；执行 `mongo-init.js` 初始化 admin 账号；
10. `pip3.6 install -r requirements.txt`；复制 `config.yaml.example → app/config.yaml`；
11. `ln -s app/tools/phantomjs /usr/bin/phantomjs`；
12. 安装 Nginx 站点配置 `misc/arl.conf → /etc/nginx/conf.d/`、dhparam.pem、执行 `gen_crt.sh` 生成自签证书；
13. 安装并启动 4 个 systemd 服务，最后启动 nginx。

安装后服务（`systemctl status`）：

| 服务 | ExecStart | 说明 |
|---|---|---|
| arl-web | `gunicorn -b 127.0.0.1:5013 app.main:arl_app -w 3` | 仅绑本机，由 nginx 对外暴露 5003 |
| arl-worker | `celery -A app.celerytask.celery worker -Q arltask -n arltask -c 2 -O fair -f arl_worker.log` | 常规任务队列 |
| arl-worker-github | `celery ... -Q arlgithub -n arlgithub -c 2 -O fair -f arl_worker.log` | GitHub 任务队列 |
| arl-scheduler | `python3.6 -m app.scheduler` | 调度进程 |

> 四个 unit 均 `After=network.target`、`WantedBy=multi-user.target`、以 root 运行，**未配置 Restart 自动拉起**；日志落 `/opt/ARL/arl_web.log`、`/opt/ARL/arl_worker.log` 及 journald。

### 2.2 Ubuntu 系统源码部署（推荐 Ubuntu 20.04 LTS）

> **依据**：ARL 官方未提供 Ubuntu 一键脚本，但官方 **arm64 镜像 `docker/ARMWorker/Dockerfile` 的基础系统正是 Ubuntu 20.04**——其 apt 包选择、massdns/ncrack 源码编译、python3.8 软链 python3.6 等做法即为官方给出的 Ubuntu 适配答案。本章按该 Dockerfile + CentOS 安装脚本 `misc/setup-arl.sh` 的对应关系整理为可直接执行的手工步骤。
>
> **版本建议**：使用 **Ubuntu 20.04**（与官方镜像同版本）。20.04 自带 Python 3.8，`requirements.txt` 中各依赖版本均兼容；22.04/24.04 的 Python 3.10+ 未经验证（PyYAML 5.4.1 等老版本包在 3.10 无预编译 wheel，安装易失败），不推荐。

#### 2.2.1 CentOS ↔ Ubuntu 部署差异对照

| 事项 | CentOS 7（官方脚本） | Ubuntu 20.04（本章） |
|---|---|---|
| 安装方式 | `misc/setup-arl.sh` 一键 | 手工分步（无官方脚本） |
| Python | yum `python36`（3.6） | apt `python3.8`，软链 `/usr/bin/python3.6`（官方 ARM 镜像同做法） |
| 中文字体（截图渲染用） | `wqy-microhei-fonts` | `fonts-wqy-microhei` |
| MongoDB | yum 官方源 4.0 | apt 官方源 4.4（focal 起才有官方包），或 Docker 跑 `mongo:4.0.27` |
| RabbitMQ | yum `rabbitmq-server` | apt `rabbitmq-server`（20.04 源内为 3.8.x，与官方 compose 版本一致） |
| nmap | rpm 7.91（nmap.org） | apt `nmap` |
| massdns | 仓库内置 `app/tools/massdns` 二进制 | 同样可用内置；保险起见源码编译覆盖（ARM 镜像做法） |
| ncrack | 下载预编译二进制 | 源码编译 0.7（ARM 镜像做法）或下载预编译，二选一 |
| nuclei / wih | amd64 包 | 按 CPU 架构选择 amd64/arm64 包 |
| systemd / nginx 配置 / 证书脚本 | 复用 `misc/*.service`、`misc/arl.conf`、`gen_crt.sh` | 完全相同，无需修改 |

#### 2.2.2 安装系统依赖

```bash
sudo apt update
sudo apt install -y python3.8 python3-pip curl wget unzip git nginx nmap \
  fontconfig fonts-wqy-microhei build-essential libssl-dev zlib1g-dev gnupg

# 对齐代码与 systemd 服务文件中的 python3.6 命令（官方 ARM 镜像同做法）
sudo ln -s /usr/bin/python3.8 /usr/bin/python3.6
sudo python3.8 -m pip install --upgrade pip
```

说明：`fonts-wqy-microhei` 供 phantomjs 截图渲染中文（对应 CentOS 的 wqy-microhei-fonts）；`build-essential/libssl-dev/zlib1g-dev` 为编译 massdns、ncrack 所需（与 ARMWorker Dockerfile builder 阶段一致）。

#### 2.2.3 安装 MongoDB

MongoDB 官方对 Ubuntu 20.04（focal）的仓库支持从 **4.4** 开始（4.0 仅有 xenial/bionic 包）。ARL 仅使用基础 CRUD / 索引 / 正则查询，4.4 完全兼容：

```bash
curl -fsSL https://www.mongodb.org/static/pgp/server-4.4.asc | \
  sudo gpg -o /usr/share/keyrings/mongodb-server-4.4.gpg --dearmor
echo "deb [ arch=amd64,arm64 signed-by=/usr/share/keyrings/mongodb-server-4.4.gpg ] https://repo.mongodb.org/apt/ubuntu focal/mongodb-org/4.4 multiverse" | \
  sudo tee /etc/apt/sources.list.d/mongodb-org-4.4.list

sudo apt update
sudo apt install -y mongodb-org
sudo systemctl enable --now mongod
```

备选方案：宿主机已装 Docker 时，可用容器运行与官方 compose 完全同版本的数据库（ARL 配置指向 `127.0.0.1:27017` 即可）：

```bash
docker run -d --name arl-mongo --restart always \
  -v arl_db:/data/db -p 127.0.0.1:27017:27017 mongo:4.0.27
```

> **注意 mongo shell 版本**：`docker/mongo-init.js` 使用旧版 `mongo` shell 的内置函数 `hex_md5()` 初始化 admin 账号，4.0/4.4 均支持；MongoDB 6.0+ 的 `mongosh` 无此函数，初始化/重置密码时需自行计算 MD5（见 5.4 节备注）。

#### 2.2.4 安装 RabbitMQ

```bash
sudo apt install -y rabbitmq-server
sudo systemctl enable --now rabbitmq-server
```

#### 2.2.5 安装扫描工具链（massdns / ncrack / nuclei / wih / GeoLite2）

**massdns**（Ubuntu 无官方包，源码编译，与 ARM 镜像同步骤）：

```bash
cd /opt
sudo git clone https://github.com/blechschmidt/massdns.git
cd massdns && sudo make
sudo cp bin/massdns /usr/local/bin/massdns
# 用本地编译产物覆盖 ARL 内置二进制（内置为 x86_64 ELF，amd64 可直接用，覆盖更稳妥）
sudo cp bin/massdns /opt/ARL/app/tools/massdns   # 若尚未 clone ARL，可在 2.2.6 完成后执行
```

**ncrack**（弱口令爆破后端，Ubuntu 无官方包，二选一）：

```bash
# 方式 A：源码编译 0.7（官方 ARM 镜像做法）
cd /opt
wget https://nmap.org/ncrack/dist/ncrack-0.7.tar.gz --no-check-certificate
tar -xzf ncrack-0.7.tar.gz && cd ncrack-0.7
./configure && make
sudo make install    # ncrack → /usr/local/bin；ncrack-services → /usr/local/share/ncrack/

# 方式 B：下载预编译二进制（setup-arl.sh 做法，仅 x86_64）
sudo wget https://github.com/1c3z/arl_files/raw/master/ncrack -O /usr/local/bin/ncrack
sudo chmod +x /usr/local/bin/ncrack
sudo mkdir -p /usr/local/share/ncrack
sudo wget https://github.com/1c3z/arl_files/raw/master/ncrack-services -O /usr/local/share/ncrack/ncrack-services
```

**nuclei 与 wih**（按 CPU 架构选择包后缀 `linux_amd64` / `linux_arm64`，下例为 amd64）：

```bash
# nuclei（官方镜像内置 3.1.3，CentOS 脚本使用 2.9.15，任选）
wget https://github.com/projectdiscovery/nuclei/releases/download/v3.1.3/nuclei_3.1.3_linux_amd64.zip
unzip nuclei_3.1.3_linux_amd64.zip && sudo mv nuclei /usr/bin/
sudo nuclei -ut        # 更新 PoC 模板，首次运行需数分钟

# wih（WebInfoHunter）
sudo wget https://github.com/1c3z/arl_files/raw/master/wih/wih_linux_amd64 -O /usr/bin/wih
sudo chmod +x /usr/bin/wih
```

**GeoLite2 离线库**（IP 归属地 / ASN）：

```bash
sudo mkdir -p /data/GeoLite2
sudo wget https://github.com/P3TERX/GeoLite.mmdb/raw/download/GeoLite2-ASN.mmdb -O /data/GeoLite2/GeoLite2-ASN.mmdb
sudo wget https://github.com/P3TERX/GeoLite.mmdb/raw/download/GeoLite2-City.mmdb -O /data/GeoLite2/GeoLite2-City.mmdb
```

#### 2.2.6 获取源码与 Python 依赖

```bash
cd /opt
sudo git clone https://github.com/TophantTechnology/ARL
sudo git clone https://github.com/1c3z/ARL-NPoC

# NPoC 插件框架（PoC / 弱口令 / 协议识别依赖）
cd /opt/ARL-NPoC
sudo python3.6 -m pip install -r requirements.txt
sudo python3.6 -m pip install -e .

# ARL 本体
cd /opt/ARL
sudo python3.6 -m pip install -r requirements.txt
sudo cp app/config.yaml.example app/config.yaml
sudo ln -sf /opt/ARL/app/tools/phantomjs /usr/bin/phantomjs   # 站点截图
```

> ARM64 主机提示：仓库内置 `app/tools/phantomjs` 为 x86_64 二进制，ARM 上无法运行（官方 ARM 镜像同样如此），截图功能将输出占位图，其余功能不受影响。
>
> **PyYAML 安装报错处理**：若 `PyYAML==5.4.1` 源码编译失败（新 pip / Cython 3 兼容问题），先执行 `python3.6 -m pip install "cython<3.0"` 再重装，或改用 `python3.6 -m pip install --only-binary=:all: -r requirements.txt` 强制使用预编译 wheel。

#### 2.2.7 初始化 RabbitMQ 与数据库账号

```bash
# RabbitMQ：与 CentOS 脚本一致
sudo rabbitmqctl add_user arl arlpassword
sudo rabbitmqctl add_vhost arlv2host
sudo rabbitmqctl set_user_tags arl arltag
sudo rabbitmqctl set_permissions -p arlv2host arl ".*" ".*" ".*"

# MongoDB：创建 admin/arlpass（依赖 2.2.3 安装的 mongo shell）
cd /opt/ARL
mongo 127.0.0.1:27017/arl docker/mongo-init.js
```

#### 2.2.8 Nginx 站点配置与证书

```bash
sudo cp /opt/ARL/misc/arl.conf /etc/nginx/conf.d/arl.conf
sudo curl https://ssl-config.mozilla.org/ffdhe2048.txt -o /etc/ssl/certs/dhparam.pem
sudo bash /opt/ARL/docker/worker/gen_crt.sh     # 生成自签证书（纯 openssl，无平台依赖）
sudo nginx -t && sudo systemctl enable --now nginx && sudo systemctl reload nginx
```

Ubuntu 官方 nginx 包的 `http` 块默认 include `/etc/nginx/conf.d/*.conf`，与 CentOS 用法一致；`arl.conf` 监听 5003，与默认站点（80 端口）不冲突。

#### 2.2.9 安装 systemd 服务

```bash
cd /opt/ARL
sudo cp misc/arl-web.service misc/arl-worker.service \
        misc/arl-worker-github.service misc/arl-scheduler.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now arl-web arl-worker arl-worker-github arl-scheduler
```

> unit 内引用的可执行路径为 `/usr/local/bin/gunicorn`、`/usr/local/bin/celery`、`/usr/bin/python3.6`。Ubuntu 下 root 身份 pip 安装通常落在 `/usr/local/bin`，安装后请核对：`which gunicorn celery`；若路径不同，`sed -i` 修改 unit 后再 `daemon-reload`。python3.6 软链已在 2.2.2 建立。

#### 2.2.10 防火墙放行（如启用 ufw）

```bash
sudo ufw allow 5003/tcp
```

#### 2.2.11 部署验证

```bash

# 2) 应用自检（与官方镜像构建期自检一致）
```

### 2.3 日常管理（misc/manage.sh）

```bash
./manage.sh start     # 依赖顺序启动：mongod → rabbitmq → arl-web → arl-worker → arl-worker-github → arl-scheduler → nginx
./manage.sh stop      # 相反顺序停止
```

## 3. 配置文件详解

配置加载机制（`app/config.py`）：代码内置默认值 → 同目录 `config.yaml` 覆盖 → **解析失败进程直接退出**。Docker 环境 `config-docker.yaml` 挂载为容器内 `/code/app/config.yaml`；源码部署使用 `/opt/ARL/app/config.yaml`。修改后需重启相应服务。

### 3.1 完整配置项（app/config.yaml.example）

```yaml

  BROKER_URL: 'amqp://arl:arlpassword@localhost:5672/arlv2host'   # Docker 中 host 改为 rabbitmq

MONGO:
  URI: 'mongodb://127.0.0.1:27017/'    # Docker: mongodb://admin:admin@mongodb:27017/
  DB: 'arl'                            # 代码内置兜底 ARLV2

QUERY_PLUGIN:                # 域名查询插件（12 源）；enable 可单独关闭
  alienvault: {enable: true}
  certspotter: {enable: true, after_id: 1, max_page: 3}
  crtsh: {enable: true}
  fofa: {enable: true}                       # 复用下方 FOFA 配置
  hunter_qax: {enable: false, api_key: '', page_size: 100, max_page: 5}
  passivetotal: {enable: false, auth_email: '', auth_key: ''}
  quake_360: {enable: false, quake_token: '', max_size: 500}
  rapiddns: {enable: true}
  securitytrails: {enable: false, api_key: ''}
  virustotal: {enable: false, api_key: ''}
  zoomeye: {enable: false, api_key: '', max_page: 20}

  CITY: '/data/GeoLite2/GeoLite2-City.mmdb'

  URL: 'https://fofa.info'
  EMAIL: ''
  KEY: ''

# 推送配置：不需要的留空即可
DINGDING: {SECRET: '', ACCESS_TOKEN: ''}
EMAIL:    {HOST: '', PORT: '', USERNAME: '', PASSWORD: '', TO: ''}
FEISHU:   {WEBHOOK_URL: '', SECRET: ''}

  TOKEN: ''                            # GitHub 泄漏监控必需
```

### 5.4 忘记密码重置

重置后使用 `admin / admin123` 登录：

```bash
# Docker 部署
docker exec -ti arl_mongodb mongo -u admin -p admin
```
```js
use arl
db.user.drop()
db.user.insert({ username: 'admin', password: hex_md5('arlsalt!@#'+'admin123') })
```

（源码部署将 mongo 命令换成本机 `mongo` shell 执行即可。）

> **mongosh（MongoDB 6.0+）备注**：新 shell 无 `hex_md5()` 函数。此时手工计算盐前 MD5 再插入：
> ```bash
> HASH=$(echo -n 'arlsalt!@#admin123' | md5sum | cut -d' ' -f1)
> mongosh arl --eval "db.user.drop(); db.user.insertOne({username:'admin', password:'$HASH'})"
> ```
> 校验逻辑见 `app/utils/user.py`：`md5('arlsalt!@#' + 明文密码)`。

## 6. 安全加固基线（生产必做）

1. **`ARL.AUTH: true`**（配置样例默认已 true；代码内置默认 false，切勿直接去掉 config.yaml）；
2. **立即修改默认口令** `admin/arlpass`（登录后改密，或按 5.4 重置）；
3. 为 `ARL.API_KEY` 设置强随机值并妥善保管（泄露等同系统控制权）；
4. `BLACK_IPS` 按网络环境收敛（默认含内网大段，防止任务探测内网造成 SSRF；纯公网场景保持默认即可）；
5. 保留 `FORBIDDEN_DOMAINS` 禁扫后缀（gov.cn/edu.cn/org.cn），合规要求；
6. 5003 端口置于内网 / VPN / 防火墙白名单之后，**不要直接暴露公网**（存在无鉴权截图接口与弱哈希口令机制）；
7. 替换自签证书（`/etc/ssl/certs/arl_web.crt|key`）为可信证书；
8. MongoDB / RabbitMQ 口令（admin/admin、arl/arlpassword）为硬编码默认值，建议修改并同步更新 config-docker.yaml。

## 7. 常见问题（FAQ）

| 现象 | 排查 |
|---|---|
| 登录页打不开 | `docker-compose ps` 检查容器；`docker logs arl_web` 看 nginx/gunicorn；安全组放行 5003 |
| 任务一直 waiting | `docker logs arl_worker`、`rabbitmqctl list_queues` 看队列；worker 是否启动成功（config.yaml 语法错误会导致进程退出，日志有 `Parse config.yaml error`） |
| 域名爆破结果为 0 | 检查出网 DNS；`dicts/dnsserver.txt` 中 DNS 服务器连通性；泛解析目标会过滤大部分结果 |
| 截图全部为占位图 | worker 容器内 phantomjs 是否可执行（`which phantomjs`）；站点本身无法访问 |
| Fofa / 鹰图 / Hunter 等插件不生效 | `QUERY_PLUGIN` 相应源 `enable: true` 且密钥已填；重启 worker 与 web |
| GitHub 监控无结果 | `GITHUB.TOKEN` 未配置或限流（worker 日志有退避记录） |
| 磁盘持续增长 | 截图目录 `image/`、Mongo 日志、`arl_db` 卷；删除历史任务时勾选「删除任务数据」级联清理 13 张结果表 |
| 时间不准 / cron 不触发 | 容器 `TZ=Asia/Shanghai` 已内置；宿主机时间漂移会影响调度（每 58s 轮询，误差 <60s） |
| Ubuntu 部署报错（PyYAML 编译失败 / 找不到 python3.6 / Mongo 装不上 4.0） | Ubuntu 非官方一键支持平台，按第 2.2 节步骤处理（软链 python3.6、安装 MongoDB 4.4、PyYAML 用 wheel 安装） |
