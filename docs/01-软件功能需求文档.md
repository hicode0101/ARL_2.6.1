## 1. 系统概述

### 1.1 系统定位

ARL 是一套面向甲方安全团队与渗透测试人员的**互联网资产侦察与管理平台**，目标是快速发现与给定目标（域名 / IP / IP 段）关联的互联网暴露资产，构建基础资产信息库，并辅助发现薄弱点与攻击面。

核心能力（对应 README「特性」与源码实现）：

1. 域名资产发现与整理（子域名爆破、第三方数据源聚合、智能字典生成）
2. IP / IP 段资产整理（端口扫描、服务识别、OS 识别、GeoIP 归属）
3. 端口扫描与服务识别（nmap 实现）
4. Web 站点指纹识别（内置规则 + 用户自定义规则引擎）
5. 资产分组管理和搜索（资产组 + 资产库 + 多维检索）
6. 任务策略配置（策略模板复用）
7. 计划任务和周期任务（定时 / cron 周期扫描）
8. GitHub 关键字监控（代码泄漏监控）
9. 域名 / IP 资产监控（周期性增量发现 + 消息推送）
10. 站点变化监控（标题 / 状态码变化检测）
11. 文件泄漏等风险检测（备份文件 / 敏感目录探测）
12. nuclei PoC 调用（CVE 类漏洞扫描）
13. WebInfoHunter（WIH）调用与监控（站点 JS 中收集子域名、AK/SK 等）
14. 风险巡航（对既有站点集合批量执行 PoC / 弱口令插件）
15. 消息推送（钉钉 / 飞书 / 企业微信 / 邮件 / 自定义 WebHook）

### 1.2 用户与角色

系统为单用户体系（MongoDB `user` 集合），典型部署下仅一个管理员账号 `admin`（默认口令 `arlpass`）。另支持两种 API 调用身份：

| 身份 | 认证方式 | 说明 |
|---|---|---|
| 交互用户（Web 前端） | 登录换取 Token，HTTP Header `Token` 携带 | 人机交互，Swagger 登记 `ApiKeyAuth` |
| 程序调用（API Key） | Header `Token: <ARL.API_KEY>` | 身份固定为 `ARL-API`，适合脚本集成 |
| 匿名访问 | 无 | 仅当 `ARL.AUTH=false` 时全站放行（有安全风险，生产禁止）；截图接口 `/api/image/` 无论如何均无鉴权 |

### 1.3 运行环境约束

- 仅支持 Linux（Docker 方式为 CentOS7 镜像，ARM 适配 Ubuntu20.04 镜像）；不支持 Windows。
- 建议：CPU 4 线程 / 内存 8G / 带宽 10M；资产发现过程发包量大，建议云服务器。
- 默认对外端口 **5003（HTTPS）**，默认账号 **admin / arlpass**。

## 3. 核心功能需求详述

### 3.1 任务下发（资产发现）—— FR-TASK

任务下发是系统最核心的功能。用户提交目标与扫描选项，系统自动拆分任务并异步执行。

#### 3.1.1 功能描述

- **入口**：`POST /api/task/`（`app/routes/task.py`，参数模型 `add_task_fields`）；业务封装 `app/helpers/task.py: submit_task_task()`。
- **目标格式**：字符串 `target`，支持空格 / 逗号分隔多个目标；每个目标可为**域名、IP、IP 段（CIDR 或范围）**。
- **自动分流**：
  - 所有 IP 目标合并为一个 `type=ip` 任务；
  - 每个域名目标生成一个独立的 `type=domain` 任务；
  - IP 任务强制关闭域名类选项（域名爆破 / 智能生成 / 域名查询插件 / ARL 历史查询）。

#### 3.1.3 任务生命周期

- **状态机**（`app/modules/__init__.py: TaskStatus`）：`waiting` → 运行中（`status` 实时流转为当前阶段名：`domain_brute` / `port_scan` / `find_site` / `ssl_cert` / `site_spider` / `poc_run` / `weak_brute` 等，风险巡航还显示 `poc 3/100` 进度）→ `done` / `error` / `stop`。
- **任务标签** `task_tag`：`task`（资产发现）/ `monitor`（资产监控）/ `risk_cruising`(风险巡航)。
- **阶段耗时**：每阶段 `{name, elapsed}` 追加到 `task.service` 数组，前端可展示各步骤耗时。
- **统计**：完成后 `task.statistic` 记录 13 类结果数量（`app/utils/arl.py: task_statistic`）。

#### 3.1.5 目标合法性校验规则（防误扫）

下发时逐目标校验（`app/helpers/task.py: get_ip_domain_list`），不满足直接拒绝：

1. IP / IP 段目标不得命中黑名单 `ARL.BLACK_IPS`（默认 `127.0.0.0/8`、`0.0.0.0/8`，docker 配置另含 `172.16.0.0/12`、`100.64.0.0/10`）—— 防 SSRF；
2. 域名不得命中本地黑名单 `dicts/blackdomain.txt` / `blackhexie.txt`（`check_domain_black`）；
3. 域名不得命中禁止后缀 `ARL.FORBIDDEN_DOMAINS`（默认 `gov.cn`、`edu.cn`、`org.cn`）；
4. 域名须通过 tld 合法性校验；域名爆破候选长度差不超过 `DOMAIN_MAX_LEN=25`。

#### 3.1.6 域名任务执行流程（功能级）

任务编排类 `app/tasks/domain.py: DomainTask`，执行顺序：

```
① 域名收集：域名爆破(massdns) → 域名查询插件 → ARL历史查询 → 智能生成(altDNS) → 搜索引擎
② IP 整理：泛解析过滤 → CDN 判定 → 端口扫描(nmap) → SSL证书 → 服务/OS识别 → geoip 归属
③ 站点发现：http/https 探活去重 → 站点抓取+指纹 → (可选)技术栈识别/截图/爬虫/文件泄漏/nuclei/WIH
④ 风险检测：Host 碰撞 → 协议识别 → PoC 扫描 → 弱口令爆破
⑤ 收尾：WIH 新域名回补 → 指纹统计/C段统计/任务统计 → 资产同步 → 消息推送 → done
```

关键算法需求：

- **泛解析过滤**：先对随机子域（`atXXXX.<domain>`）解析得到泛解析 IP 集合，凡解析结果命中该集合或同一 record 出现次数超阈值（爆破 35 次 / 智能生成 15 次）的记录丢弃；
- **CDN 判定**：基于 `dicts/cdn_info.json` 的 IP 段 / CNAME 后缀匹配 + 关键字（gslb/dns/cache）+ 多 A 记录启发（`app/utils/cdn.py`）;
- **智能字典生成**：dnsgen 式五种变换（`DnsGen` 类），并发默认 1500（`ALT_DNS_CONCURRENT`）；
- **同内容去重**：同主机 http/https 页面内容相同仅保留一个站点。

### 3.2 IP 任务 —— FR-IPTASK

- 目标为 IP / IP 段时的任务形态：端口扫描（nmap，公网 IP 附 GeoIP ASN/城市归属，`ip_type` 判定 PUBLIC/PRIVATE）→ 服务入库 → SSL 证书 → 站点发现（ip:port 构造 URL 探活）→ 后续站点处理与风险检测与域名任务一致（`app/tasks/ip.py: IPTask`）。
- 单主机开放端口超过 600 个时仅保留 80/443，防止误报泛滥。
- FOFA 任务（`POST /api/task_fofa/submit`）拉取 Fofa 查询结果的 IP 列表后复用 IP 任务管道执行。

### 3.3 风险巡航 —— FR-RISK

对既有站点 / 服务目标批量执行 PoC 与弱口令检测（`app/tasks/poc.py: RiskCruising`）：

1. 目标来源两种：手工填写目标列表 `cruising_target`，或先在站点 / 资产站点页把查询结果**保存为结果集**（`GET /api/site/save_result_set`、`GET /api/asset_site/save_result_set`），再引用 `result_set_id`（结果集消费后即删除，一次性使用）;
2. 支持 PoC 插件选择（`poc_config`）、弱口令插件选择（`brute_config`）;
3. 执行过程中任务状态实时显示进度（`poc x/total` / `brute x/total`）;
4. 漏洞结果统一写入 `vuln` 集合，按 `plg_name` / `vul_name` / `target` 查询。

### 3.4 资产组管理 —— FR-ASSET

资产组（asset scope）是资产库的组织单元，支持两类范围：`domain`（域名）与 `ip`（IP 段）。

| 需求编号 | 需求 | 说明 |
|---|---|---|
| FR-ASSET-01 | 创建资产组 | 名称 + 范围（可多个）+ 黑名单范围；IP 自动归一化为 CIDR（`asset_scope.scope_array`） |
| FR-ASSET-02 | 范围追加 / 删除 | 追加时重复范围报错（code 603） |
| FR-ASSET-03 | 资产组删除 | 级联删除组内 `asset_domain/asset_site/asset_ip/asset_wih` 及监控任务 |
| FR-ASSET-04 | 资产四库查询 | 域名 / 站点 / IP / WIH 四类资产按 `scope_id` 查询，支持多维过滤与时间范围（`update_date__dgt/__dlt`） |
| FR-ASSET-05 | 手工添加资产 | 添加域名 / 站点到资产组会实际下发扫描任务（域名添加用 test 档爆破+端口，站点添加走 risk_cruising 策略选项）；IP 类资产组不允许添加站点（code 1608） |
| FR-ASSET-06 | 站点标签 | 手工增删标签（`tag` 数组）；系统自动标签：`入口` / `无效`（`app/services/autoTag.py`） |
| FR-ASSET-07 | 资产导出 | 域名 txt / 站点 txt / IP 端口 / 纯 IP / 纯域名 / WIH 内容导出 |
| FR-ASSET-08 | 任务结果同步 | 域名任务结束后可将结果手动同步到资产组（`POST /api/task/sync/`），或通过 `related_scope_id` 自动同步；同步去重键：域名=domain、站点=site(含 `?`/`;` 前缀粗判)、IP=ip、WIH=fnv_hash |
| FR-ASSET-09 | 目标反查资产组 | `GET /api/task/sync_scope/?target=` 返回包含该域名的资产组列表 |

### 3.5 资产监控 —— FR-MONITOR

对资产组配置周期任务，实现资产的持续增量发现与变化感知。由独立调度进程 `app/scheduler.py`（每 58 秒轮询 `scheduler` 集合）驱动。

| 需求编号 | 需求 | 约束 |
|---|---|---|
| FR-MON-01 | 域名监控 | 域名类资产组；`interval ≥ 21600 秒（6 小时）`；同一域名不允许重复建监控（code 699）；默认选项：大字典爆破 + ARL 历史查询 + 域名插件 + test 档端口扫描 |
| FR-MON-02 | IP 监控 | IP 类资产组，周期端口扫描，仅将**新 IP / 新端口**增量写入资产库 |
| FR-MON-03 | 站点更新监控 | 重访资产组全部站点，比对标题 / 状态码变化；无站点资产组不允许重复创建（code 1607） |
| FR-MON-04 | WIH 更新监控 | 周期对资产组站点执行 WIH，以 fnv_hash 去重入 `asset_wih` |
| FR-MON-05 | 监控任务控制 | 停止（单个 / 批量）/ 恢复（单个 / 批量）/ 删除；状态 `running`/`stop` |
| FR-MON-06 | 新资产推送 | 监控发现新资产后推送钉钉 / 飞书 / 企业微信 / 邮件（每类资产最多附 10 条样例），并可选触发自定义 WebHook（POST JSON，Header 带 Token） |
| FR-MON-07 | 运行记账 | 记录 `run_number`（已运行次数）、`last_run_date`、`next_run_date` |

### 3.6 计划任务 —— FR-SCHEDULE

基于策略的定时 / 周期扫描（`app/routes/task_schedule.py`、`app/helpers/task_schedule.py`）：

- 类型 `future_scan`：一次性定时任务，`start_date` 必填且须晚于当前时间；
- 类型 `recurrent_scan`：cron 周期任务，`cron` 表达式校验（`crontab` 库），最小间隔 6 小时（code 1502/700）；
- 任务标签：`task`（资产发现）/ `risk_cruising`（风险巡航）；
- 执行时按 `policy_id` 展开策略为任务选项，任务名自动加前缀「周期任务-」/「定时任务-」；
- 状态机：`scheduled` / `done` / `stop` / `error`；支持停止 / 恢复 / 删除。

### 3.7 任务策略 —— FR-POLICY

策略是任务选项的持久化模板（`app/routes/policy.py`），三类配置段：

- `domain_config`：域名收集选项（爆破、字典档位、智能生成、ARL 历史查询、域名插件）;
- `ip_config`：端口扫描选项（含自定义端口、nmap 调优参数、跳过 CDN）;
- `site_config`：站点处理选项（识别、截图、搜索引擎、爬虫、nuclei、WIH）;
- `poc_config` / `brute_config`：勾选启用的 PoC / 弱口令插件（校验插件存在于 `poc` 集合）;
- `file_leak`、`npoc_service_detection` 全局开关;
- `scope_config`：关联资产组（用于任务完成自动同步）。

编辑接口采用白名单键递归合并，未知字段自动过滤。

### 3.8 GitHub 泄漏监控 —— FR-GITHUB

| 需求编号 | 需求 | 说明 |
|---|---|---|
| FR-GH-01 | 泄漏搜索任务 | 给定关键字（必填），调用 GitHub Code Search API（`GITHUB.TOKEN` 鉴权）搜索代码并抓取文件内容与 commit 时间，入 `github_result` |
| FR-GH-02 | 噪音过滤 | 按路径关键字（如 `/adblock`）与内容关键字（如 `DOMAIN-SUFFIX`）过滤误报 |
| FR-GH-03 | 监控周期任务 | 关键字 + cron 表达式（最小间隔 6 小时），由调度进程周期下发监控任务 |
| FR-GH-04 | 增量去重 | 以 `md5(repo/path)` 存 `github_hash` 集合，仅新结果写 `github_monitor_result` |
| FR-GH-05 | 泄漏报告推送 | 新结果按仓库分组生成 HTML/Markdown 报告，推送钉钉 + 邮件（每仓库最多 5 条、摘录关键字前后 8 行） |
| FR-GH-06 | 限速处理 | API 限流时按 20+15×N 秒退避重试（最多 3 次），调用间隔 2.5s |
| FR-GH-07 | 任务控制 | 任务与监控任务的停止 / 删除（级联删结果）/ 修改（关键字与 cron） |

### 3.9 指纹识别与指纹库 —— FR-FINGER

- **识别规则双引擎**：
  1. 内置规则 `dicts/webapp.json`（html / header / title / favicon_hash 四类规则，`app/utils/fingerprint.py`）；
  2. 用户自定义规则库（MongoDB `fingerprint` 集合），采用**人类可读规则表达式**，如 `body="xxx" || title="yyy" && header="zzz" || icon_hash="123456"`，支持 `=`(包含) / `==` / `!=` / `&&` / `||` / `!` 运算符（pyparsing 解析，`app/services/expr.py`），解析结果按 MD5 缓存，规则全量进程内缓存（`fingerprint_cache`）。
- **指纹管理**：单条添加（规则表达式校验 + 重复检测 code 1609）、YAML 批量上传（返回成功 / 失败 / 重复计数）、全部导出 YAML、按名称查询、删除。
- **指纹统计**：任务完成后统计每个指纹命中站点数（`stat_finger`）。

### 3.10 文件泄漏检测 —— FR-FILELEAK

对站点探测敏感 / 备份文件（`app/services/fileLeak.py`、`arl_tool/fileleakV2.py` 提供独立 CLI 版本）：

- 字典：`dicts/file_top_2000.txt`（约 1300 条路径，可经 `ARL.FILE_LEAK_DICT` 替换）+ 由域名各段与 URL 目录名动态拼接的备份后缀（`.zip` / `.rar` / `.tar.gz` / `.7z` / `_bak.rar` / `.war` 等）;
- 误报消除：404 基线（随机路径建立）、页面相似度比对（去 payload 后长度差 ≤5 或 quick_ratio ≥0.8 判同页）、404 页面特征（标题含「404/不存在/错误/防火墙」、302 跳转）、二次变体校验（对 200 页面追加随机后缀复测）;
- 结果含 title / url / content_length / status_code，入 `fileleak` 集合。

### 3.11 WebInfoHunter（WIH）—— FR-WIH

- 调用外部 Go 工具 `wih`，基于规则 `dicts/wih_rules.yml` 从站点 JS 文件中提取**子域名、AK/SK 云密钥、敏感信息**;
- 三种使用形态：域名 / IP 任务内开启（`web_info_hunter`）、资产 WIH 监控周期执行、手动添加资产站点任务;
- 结果字段：`record_type`（记录类型）、`content`、`site`（来源站点）、`source`（来源 JS URL）、`fnv_hash`（去重键）;
- 任务内发现的**新域名**会自动回补执行域名解析与站点抓取（`domain_site_update`），随后并入资产同步。

### 3.12 漏洞检测（NPoC + nuclei）—— FR-VULN

| 通道 | 说明 | 结果集 |
|---|---|---|
| NPoC 漏洞 PoC | 外部框架 ARL-NPoC（`xing` 包）插件化执行，插件清单同步入 `poc` 集合（分类：漏洞PoC / 服务弱口令 / 应用弱口令 / 协议识别） | `vuln` |
| 弱口令爆破 | NPoC BRUTE 插件，底层 ncrack | `vuln` |
| nuclei | 外部 nuclei 二进制（镜像内置 3.1.3），`-tags cve -severity low,medium,high,critical -type http`，兼容新旧 JSON 参数 | `nuclei_result` |
| Host 碰撞 | 以域名为 Host 请求公网 IP，与 404 基线相似度 0.9 比对 | `vuln`（vul_name=发现Host碰撞漏洞） |
| 协议识别 | NPoC SNIFFER 插件识别非 80/443 端口协议 | `npoc_service` |

用户可通过上传目录（docker 挂载 `./poc → /opt/ARL-NPoC/xing/plugins/upload_poc`）扩展 PoC，经 `GET /api/poc/sync/` 重新同步插件清单。

### 3.13 数据检索与导出 —— FR-QUERY-EXPORT

- **通用列表查询**（`app/routes/__init__.py: ARLResource`）：分页 `page/size`，排序 `order`（`-` 降序前缀，多字段逗号分隔），字符串参数默认正则模糊匹配（忽略大小写），`task_id/task_tag/ip_type/scope_id/type` 精确匹配，支持后缀操作符 `__dgt/__dlt/__neq/__not`（时间大于 / 小于、不等于、不包含）。
- **导出**：
  - 单任务完整 Excel 报告（`GET /api/export/{task_id}`）：站点、IP、服务、域名、资产统计（Top20 占比）多 Sheet；
  - 按任务批量导出 txt：站点 / 域名 / IP / URL / C 段 / ip:port；
  - 按资产组批量导出：asset_ip / asset_domain / asset_site / asset_wih。

### 3.14 系统管理 —— FR-SYS

## 6. 业务规则与约束汇总

1. 监控 / 周期 / GitHub 监控类任务的最小运行间隔统一为 **6 小时**；
2. 任务仅在其处于 `done/stop/error` 终态时才可删除 / 重启；删除任务可选级联删除 13 张结果表数据；
3. 监控任务不支持重启；带结果集的风险巡航任务不支持重启；
4. IP 任务强制关闭一切域名收集选项；
5. 任务目标含 `{fuzz}` 占位符时进入模糊字典爆破模式，跳过插件 / ARL 历史 / 搜索引擎；
6. FOFA VIP 等级为 0（注册用户）拒绝使用，等级 1 限 100 条；
7. 同一账号同时仅一个有效 Token，重复登录覆盖旧 Token，修改密码后强制登出；
8. 配置文件解析失败时进程直接退出（fail-fast）。
