## 1. 通用约定

### 1.1 认证

- **认证方式**：API Key（HTTP Header），Header 名为 **`Token`**（Swagger 登记 `ApiKeyAuth`）；同时兼容 URL 参数 `?token=xxx`。
- **Token 获取**：`POST /api/user/login` 成功后返回，存于 MongoDB `user.token`；无过期时间；同账号重复登录覆盖旧 Token。
- **API_KEY 模式**：Header `Token` 值等于配置 `ARL.API_KEY` 时以 `ARL-API` 身份放行，适合脚本集成。
- **认证开关**：`ARL.AUTH=false` 时全部接口（除登录）匿名放行——生产必须置 `true`。
- **例外**：`GET /api/image/{task_id}/{file}` 截图接口**无鉴权**。

### 1.2 通用查询参数（所有 GET 列表接口）

| 参数 | 类型 | 说明 |
|---|---|---|
| page | Integer | 页码，默认 1 |
| size | Integer | 每页条数，默认 10（上限 100000） |
| order | String | 排序字段，默认 `-_id`；`-` 前缀降序，`+`/无前缀升序，多字段逗号分隔 |
| `<字段>` | String | 过滤条件；字符串默认 **正则模糊匹配（忽略大小写）**；`task_id/task_tag/ip_type/scope_id/type` 为精确匹配 |
| `<字段>__dgt / __dlt` | 时间 | 大于 / 小于指定时间（`%Y-%m-%d %H:%M:%S`） |
| `<字段>__neq / __not` | — | 不等于 / 不包含（正则取反） |
| _id | String | 文档 ID（自动转 ObjectId） |

实现：`app/routes/__init__.py: ARLResource.build_db_query`。

### 1.3 响应结构

列表查询（code 恒为 200，业务错误靠 HTTP 层之外的业务码字段不存在——列表接口查询失败抛异常）：

```json
{
  "page": 1, "size": 10, "total": 123,
  "items": [ { "_id": "ObjectId串", "...": "文档字段", "save_date": "...", "update_date": "..." } ],
  "query": { "实际执行的 Mongo 查询条件（回显，便于调试）" },
  "code": 200
}
```

操作类响应（`app/utils/__init__.py: build_ret`）：

```json
{ "message": "success", "code": 200, "data": { } }
```

## 3. 典型调用示例

### 3.1 登录并下发域名任务

```bash
# 1) 登录
curl -sk -X POST 'https://127.0.0.1:5003/api/user/login' \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"arlpass"}'
# → {"code":200,"data":{"token":"<TOKEN>",...}}

# 2) 下发任务（域名 + 选项）
curl -sk -X POST 'https://127.0.0.1:5003/api/task/' \
  -H 'Token: <TOKEN>' -H 'Content-Type: application/json' \
  -d '{
    "name":"demo-task",
    "target":"example.com",
    "domain_brute": true, "domain_brute_type": "big",
    "port_scan": true, "port_scan_type": "top100",
    "service_detection": false,
    "site_identify": true, "site_capture": true,
    "file_leak": true
  }'
# → {"code":200,"message":"success","items":[{"task_id":"...","status":"waiting",...}]}

# 3) 轮询任务状态
curl -sk 'https://127.0.0.1:5003/api/task/?_id=<task_id>' -H 'Token: <TOKEN>'

# 4) 查询站点结果（分页 + 指纹过滤）
curl -sk 'https://127.0.0.1:5003/api/site/?task_id=<task_id>&finger.name=Nginx&page=1&size=20&order=-update_date' \
  -H 'Token: <TOKEN>'
```

### 3.2 使用 API_KEY（脚本集成）

配置 `ARL.API_KEY` 后，所有接口以 `Token: <API_KEY>` 调用即可，无需登录。

## 4. 接口设计特点小结

1. **统一资源模型**：34 个 Namespace 大量复用 `ARLResource` 基类（分页 / 过滤 / 排序 / 导出），新增资源仅需声明集合与查询模型；
2. **正则模糊查询**：字符串条件默认模糊匹配，配合 `__dgt/__dlt/__neq/__not` 后缀操作符覆盖 90% 检索场景，前端无需构造 Mongo 查询；
3. **异步任务语义**：一切耗时操作（扫描、同步、GitHub 搜索）均为「落库 waiting → Celery 投递 → 状态机流转」，接口即时返回 task_id；
4. **认证简单化**：单 Header `Token`，无 OAuth / JWT；集成成本最低但需在部署侧补偿安全措施（AUTH=true、改默认口令、网络隔离）。
