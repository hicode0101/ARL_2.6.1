# ARL 数据库设计文档

| 项目 | 内容 |
|---|---|
| 数据库 | MongoDB 4.0.27 |
| 默认库名 | 配置决定：`app/config.yaml.example` 为 `arl`；代码内置兜底 `ARLV2` |
| 访问方式 | pymongo 3.13.0，统一入口 `app/utils/conn.py: conn_db('<集合名>')`，无 ORM，schemaless |
| 设计特点 | 无模式文档模型；以 `task_id` / `scope_id` 两个外键维系任务域与资产域；无存储过程 / 事务 / TTL |

> 本文所有集合与字段均从源码插入 / 更新语句归纳，标注来源代码位置。

## 1. 数据模型总览

### 1.1 集合清单（共 31 个）

**任务域（按 task_id 关联 task）**

| 集合 | 用途 |
|---|---|
| `task` | 任务主表（资产发现 / 监控 / 风险巡航 / FOFA / 添加站点 / WIH 更新） |
| `site` | 任务发现的站点 |
| `domain` | 任务发现的子域名 |
| `ip` | 任务发现的 IP（含端口、OS、GeoIP、CDN） |
| `cert` | SSL 证书 |
| `service` | 服务汇总（按服务名聚合的 ip:port/product/version） |
| `url` | 爬虫 / 搜索引擎发现的 URL |
| `vuln` | 漏洞（PoC / 弱口令 / Host 碰撞） |
| `fileleak` | 文件泄漏 |
| `npoc_service` | Python 协议识别结果 |
| `nuclei_result` | nuclei 扫描结果 |
| `wih` | WebInfoHunter 记录（任务级） |
| `cip` | C 段 IP 聚合统计 |
| `stat_finger` | 任务指纹统计 |

**资产域（按 scope_id 关联 asset_scope）**

| 集合 | 用途 |
|---|---|
| `asset_scope` | 资产组（范围定义 + 黑名单） |
| `asset_domain` | 资产组域名库 |
| `asset_site` | 资产组站点库 |
| `asset_ip` | 资产组 IP 库 |
| `asset_wih` | 资产组 WIH 记录库 |

**调度域**

| 集合 | 用途 |
|---|---|
| `scheduler` | 资产监控 job（域名 / IP / 站点更新 / WIH 更新监控） |
| `task_schedule` | 计划任务（定时 / 周期） |
| `policy` | 任务策略模板 |
| `result_set` | 站点查询结果集（供风险巡航一次性消费） |

**GitHub 域**

| 集合 | 用途 |
|---|---|
| `github_task` | GitHub 泄漏搜索任务 |
| `github_result` | 普通任务结果 |
| `github_scheduler` | 监控周期任务定义 |
| `github_monitor_result` | 监控增量结果 |
| `github_hash` | `md5(repo/path)` 去重索引 |

**基础域**

| 集合 | 用途 |
|---|---|
| `user` | 用户（口令哈希 + token） |
| `fingerprint` | 用户自定义 Web 指纹规则 |
| `poc` | PoC 插件清单（xing 框架同步） |

> 与旧版 / 网传资料的名称差异（源码核实）：**不存在** `ip_domain`（IP 与域名合并在 `ip.domain` 数组）、`nuclei_leak`（实为 `nuclei_result`）、`github_monitor`（拆为 scheduler/monitor_result/hash 三表）、`wih_task`/`wih_result`（统一 `wih`）、`asset_url`（资产库只同步 site/domain/ip/wih 四类）、`task_trace`（进度由 task.status + task.service 表达）。

### 1.2 实体关系图（文字版）

```
user(1) ── token 认证 ──► 全部 API

asset_scope(1)┬─◄ scope_id ── asset_domain / asset_site / asset_ip / asset_wih
              ├─◄ scope_id ── scheduler(监控 job)
              └─◄ related_scope_id(options 内) ── task(自动同步)

task(1)┬─◄ task_id ── site/domain/ip/cert/service/url/vuln/fileleak/
       │              npoc_service/nuclei_result/wih/cip/stat_finger  (13 张结果表)
       ├─ result_set_id ──► result_set(消费后删除)
       └─ options.related_scope_id ──► asset_scope

policy(1) ── policy_id ──► task_schedule(计划任务) / task(经策略展开 options)
scheduler(job) ── 投递 ──► task(monitor 类)

github_scheduler(1)┬─◄ github_scheduler_id ── github_task(监控触发的任务)
                   ├─◄ github_scheduler_id ── github_monitor_result
                   └─◄ github_scheduler_id ── github_hash
github_task(1) ──◄ github_task_id ── github_result
```

## 2. 各集合字段设计

> 通用约定：所有文档主键 `_id`（ObjectId，API 层转字符串）；多数文档带 `save_date` / `update_date`；资产域两字段为 datetime 对象，任务域多为字符串（`%Y-%m-%d %H:%M:%S`）。

### 2.1 user

来源：`docker/mongo-init.js`、`app/utils/user.py`。

| 字段 | 类型 | 说明 |
|---|---|---|
| username | String | 用户名，初始 `admin` |
| password | String | `md5('arlsalt!@#' + 明文口令)` 十六进制小写（盐硬编码） |
| token | String/Null | 登录 token（`md5(50 位随机串)`），登出 / 改密置 Null；无过期时间；同账号单 token |

## 3. 索引设计

全部索引集中在 `app/utils/arlupdate.py: create_index()`，应用启动时幂等创建，均为**单字段索引**：

| 集合 | 索引字段 |
|---|---|
| cert | task_id |
| domain | task_id、domain |
| fileleak | task_id |
| ip | task_id |
| npoc_service | task_id |
| site | task_id、status、title、hostname、site、http_server |
| service | task_id |
| url | task_id |
| vuln | task_id |
| asset_ip | scope_id |
| asset_site | scope_id |
| asset_domain | scope_id、domain |
| github_result | github_task_id |
| github_monitor_result | github_scheduler_id |
| wih | task_id、record_type、fnv_hash |

其余集合依赖 `_id` 默认索引。设计意图：索引主要服务于 `task_id` / `scope_id` 两个高频外键；通用列表查询大量使用正则（`$regex`，忽略大小写），无法利用普通索引，大数据量下列表检索为性能瓶颈点。

## 4. 初始化与升级（arl_update）

入口：`app/main.py` import 时调用 `app/utils/arlupdate.py: arl_update()`（Web 进程启动执行一次）。

1. `flask routes` 模式运行时跳过；
2. `npoc_info_update()`：`poc` 集合为空时从 xing 框架同步插件元数据（线程锁防并发）；
3. 写锁文件 `app/tmp/arl_update.lock`，完成后不重复执行；
4. `update_task_tag()`：为缺 `task_tag` 的历史任务补 `task`（数据迁移）；
5. `create_index()`：按第 3 节建索引。

数据库初始用户由 `docker/mongo-init.js` 在 Mongo 容器**首次初始化**时创建：

```js
db.user.drop()
db.user.insert({ username: 'admin', password: hex_md5('arlsalt!@#'+'arlpass') })
```

## 5. 数据生命周期与清理

系统**没有** TTL 索引与自动清理任务，全部删除均为用户触发、按外键级联：

| 触发 | 级联范围 |
|---|---|
| 删除任务（`POST /api/task/delete/`，仅终态任务） | 可选 `del_task_data=True` 时清理 cert/domain/fileleak/ip/service/site/url/vuln/cip/npoc_service/wih/nuclei_result/stat_finger 共 13 张结果表 |
| 删除资产组 | asset_domain / asset_site / asset_ip / asset_wih / scheduler |
| 删除 GitHub 监控 | github_hash + github_monitor_result |
| 删除 GitHub 任务 | github_result |
| 刷新 PoC 库 | poc 全清后重同步 |
| 结果集消费 | 读取 items 后删除 |
| 任务投递失败 | 回滚删除 waiting 任务文档 |

增长风险点：`github_hash` 只在删除监控任务时清理；未被引用的 `result_set` 永久留存；长期运行的建议人工定期清理历史任务（含级联数据）。

---

## 6. 数据一致性设计要点

1. **任务投递原子性**：先插 task 文档再投递 Celery，投递异常立即删除文档（`helpers/task.py: submit_task`）；
2. **同步互斥**：`task.sync_status` 状态机（default→waiting→running/error）防止重复同步；
3. **增量一致性**：监控任务通过「内存差集 + 删旧插新 / $set 合并」保证资产库与最新扫描视图一致；
4. **去重键设计**：资产库每类资产有明确业务唯一键（domain/site/ip/fnv_hash），任务结果表无唯一约束（同一域名可在多任务中重复出现，按 task_id 隔离）；
5. **无事务**：MongoDB 4.0 单机无多文档事务，跨集合一致性依赖「先删后插」「差集计算后落库」等应用层顺序控制。
